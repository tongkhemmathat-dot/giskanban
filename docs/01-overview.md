# 01 — ภาพรวมและขอบเขต

## 1. ปัญหาที่แก้

ทีม System Engineer รับงานกระจัดกระจายจาก Line, อีเมล, โทรศัพท์ ทำให้:
- ไม่รู้ว่าใครแจ้งงาน แจ้งเมื่อไหร่
- งานเร่งด่วนหล่นหาย ไม่มี SLA
- งานที่มีหลายขั้นตอน (เช่น upgrade software) ไม่รู้ว่าทำถึงไหน
- หัวหน้าไม่เห็นภาพรวมภาระงานของทีม

## 2. กลุ่มผู้ใช้

| กลุ่ม | จำนวน | ใช้ทำอะไร |
|---|---|---|
| System Engineer | 5–12 คน | สร้างใบงาน, อัปเดตขั้นตอน, ปิดงาน |
| หัวหน้าทีม | 1–2 คน | ดู Dashboard, ติดตามงานเกินกำหนด |
| ผู้แจ้งงานภายใน | ตามสะดวก | สร้างใบงานแล้วระบุชื่อตัวเอง |

> ไม่แบ่ง role ในระบบ — ทุกคนใช้สิทธิ์เท่ากัน แยกด้วย "ชื่อผู้สร้าง" เท่านั้น

## 3. ขอบเขต

### ✅ อยู่ในขอบเขต (In Scope)

- Kanban board ลาก-วาง 6 คอลัมน์
- ใบงาน 4 ประเภท: Incident / Service Request / Change / Maintenance
- ขั้นตอนย่อยพร้อมแม่แบบสำเร็จรูป
- SLA อัตโนมัติตาม priority
- ความคิดเห็น, ไฟล์แนบ, บันทึกเวลา, ประวัติกิจกรรม
- Dashboard + รายงานพื้นฐาน
- ค้นหา + กรอง

### ❌ นอกขอบเขต (Out of Scope — v1)

- ระบบล็อกอิน / สิทธิ์ / role
- แจ้งเตือนทางอีเมล / Line Notify (พิจารณา v2)
- Mobile app (ใช้ responsive web แทน)
- เชื่อมต่อ monitoring อัตโนมัติ (Zabbix / PRTG)
- Multi-tenant / หลายบอร์ด
- รายงาน export PDF

## 4. คำศัพท์ (Glossary)

| คำ | ความหมาย |
|---|---|
| **Card / ใบงาน** | หน่วยงาน 1 ชิ้น มีรหัส `JC-000123` |
| **List / คอลัมน์** | สถานะของงาน เช่น Backlog, In Progress |
| **Subtask / ขั้นตอนย่อย** | ขั้นตอนภายในใบงาน ติ๊กเสร็จทีละข้อ |
| **Template / แม่แบบ** | ชุดขั้นตอนสำเร็จรูปที่ใช้ซ้ำได้ |
| **Creator / ผู้สร้าง** | คนที่แจ้งงาน — บังคับระบุตอนสร้าง |
| **Assignee / ผู้รับผิดชอบ** | คนที่ลงมือทำ (มีได้หลายคน) |
| **SLA** | เวลาที่ต้องปิดงานให้เสร็จ คำนวณจาก priority |
| **WIP Limit** | จำนวนงานสูงสุดที่คอลัมน์รับได้ (เตือนเมื่อเกิน) |

## 5. ตัวชี้วัดความสำเร็จ

1. ทุกใบงานรู้ว่าใครแจ้ง ภายใน 1 คลิก
2. งานเกินกำหนดถูกมองเห็นทันทีบนหน้าแรก
3. งานที่มีหลายขั้นตอนแสดง % ความคืบหน้าได้
4. สร้างใบงานใหม่เสร็จภายใน 30 วินาที
